简历项目经验怎么写：STAR 法则 + 量化公式

项目经历是简历里最容易被写废、也最容易出彩的部分。核心就一条：写清楚你做了什么、带来了什么结果，而不是罗列你'参与了'什么。

一、最基础的量化公式

动作 + 技术/方法 + 结果（数字）

❌ 反面：「负责公司官网的前端开发。」
✅ 正面：「独立完成官网前端重构（Vue3），首屏加载从 3.1s 优化到 1.0s，跳出率下降 22%。」

二、STAR 法则拆解

  • S 情境：项目背景/业务问题是什么
  • T 任务：你具体负责哪一块
  • A 行动：用了什么方法/技术
  • R 结果：可量化的产出（用户、性能、收入、效率）

每条项目经历写 2–4 个 bullet，优先放有数字的那条。

三、没经验怎么写项目

没有实习≠没项目。以下都算：

  • 🎓 课程设计 / 毕业设计
  • 💻 个人 GitHub 项目 / 小程序 / 博客
  • 🏆 比赛项目（数学建模、互联网+、挑战杯）
  • 📊 课程大作业（哪怕只是数据分析报告）
  • 📱 帮社团/朋友做的公众号、海报、视频
示例：「全国大学生数学建模（S），负责数据清洗与可视化（T），用 Python pandas 处理 10 万条数据并搭建看板（A），团队获省级二等奖（R）。」

四、程序员项目写法

  • 写技术栈：语言、框架、中间件、云。
  • 写复杂度：QPS、数据量、并发、用户规模。
  • 写你主导的部分，别把团队成果全揽。
  • 写难点突破：性能瓶颈、一致性、稳定性。

五、避坑

🚫 '参与了 XX 项目'——参与不等于贡献
🚫 只写技术名词堆砌，没说解决了什么问题
🚫 结果全是定性描述没有数字
✅ 每条都能在面试里被追问细节
