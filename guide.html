一、8 大模块，逐个说清怎么写

90% 的岗位，简历按这个顺序排，缺哪个补哪个。每个模块都给出「写什么 / 写多少 / 常见错误」。

1. 基本信息

写什么：姓名、手机、邮箱、所在城市；有作品可加 GitHub / 个人主页 / 作品集链接。
写多少：一行内解决，放在最顶部。
常见错误：写身份证号、身高体重、婚育状况、家庭住址 —— 这些既不必要，还可能引发偏见或被滥用。

2. 求职意向

写什么：一句话点明目标岗位，例如「求职意向：Java 后端开发工程师（3 年经验）」。
为什么写：ATS 用它做岗位匹配，HR 一眼知道你要什么。转行、跨岗时尤其必要。
常见错误：写「寻求有发展空间的岗位」这类模糊表述，等于没写。

3. 个人简介（Summary）

写什么：2–3 句，公式 = 身份 + 年限 + 最擅长的领域 + 最有说服力的一个成果。
写多少：不超过 3 行；这是全篇唯一「先看」的区域，务必放最硬的成果。

❌ 弱：工作认真负责，有良好的团队精神和沟通能力，希望能找到一个施展才华的平台。
✅ 强：5 年 Java 后端经验，专注高并发交易系统；主导订单系统重构，接口 QPS 从 800 提升至 5000。

4. 工作经历

写什么：公司 → 岗位 → 在职时间（倒序），每条经历 2–4 个要点，每个要点用 STAR/CAR 写。
写多少：最近一段写 4 条，越久远越精简（1–2 条）。
常见错误：把「岗位职责」照抄一遍。公司要的是你的成果，不是职位说明书。

5. 项目经历

写什么：项目名称、你的角色、时间、项目背景一句话、你做的事、可量化结果。技术岗可写清技术栈与难点。
挑哪些：只留 2–3 个最能证明目标岗位能力的，与岗位无关的项目大胆删。
常见错误：写「参与了某项目」，看不出你具体负责哪块、起了什么作用。

6. 教育背景

写什么：学校、专业、学历、起止时间。应届生补充 GPA（排名靠前才写）、核心课程、奖学金、竞赛荣誉。
写多少：应届生放工作经历之前；工作 3 年以上放后面，一两行即可。
常见错误：GPA 只有 2.8 也硬写；或把中学经历写进资深简历。

7. 专业技能

写什么：按「岗位核心技能 → 加分技能 → 工具」分组罗列，用短标签而非长句。
写多少：8–15 条最佳，太多显得水，太少显得薄。
常见错误：写「精通 Office」「熟练使用电脑」；或把不熟的也写「精通」，面试一问就穿帮。分级规范见 行业技能清单。

8. 证书 / 荣誉 / 其他

写什么：与岗位强相关的证书（会计中级、软考、教师资格、执业医师）、语言成绩、专利、发表物。
常见错误：把无关证书堆一排（如普通话二级甲等投后端岗），挤占关键信息的位置。

二、STAR / CAR 法则：把「做了什么」写成「带来了什么」

大多数简历死在「负责 XXX 工作」这种空话。用 STAR 拆解，再用 CAR 精简成一句话。

维度含义示例
S 情境当时面对什么问题首屏加载慢，LCP 3.2s
T 任务你负责什么牵头性能优化
A 行动你具体做了什么引入懒加载 + 资源压缩 + CDN 改造
R 结果数据结果LCP 降至 1.1s，注册转化 +12%

写进简历时通常压缩为 CAR：C 挑战 → A 行动 → R 结果，一句话说完，动词开头。

❌ 前：负责公司前端开发，参与多个项目，完成上级交办的任务。
✅ 后：主导组件库建设（C），统一 30+ 业务线 UI 规范（A），研发效率 +40%、线上 bug -25%（R）。
❌ 前：负责招聘工作，办理员工入职离职手续。
✅ 后：承接年均 200+ 岗位招聘（C），优化面试流程与渠道结构（A），到岗率 92%、平均到岗周期缩短 9 天（R）。
❌ 前：负责店铺日常运营，包括上架和推广。
✅ 后：操盘单店全年运营（C），重构选品与投放策略（A），年 GMV 6000 万、同比 +45%（R）。

三、量化成果：7 类口径，没有数字就套公式

能写数字的地方一定写数字。想不出数字时，从这七类里去「找」：

类别常见口径例句片段
效率提升 X%、节省 X 人天、缩短 X 小时研发效率提升 40%，月结周期从 7 天缩至 3 天
规模支撑 X 万日活、X 万次查询、X 万 GMV支撑日均 200 万次查询，管理对公客户 120+ 户
质量bug -X%、满意度 X 分、故障归零 X 天线上 bug 下降 25%，连续 3 年审计零重大问题
增长用户 +X%、留存 X%、营收 +X%次月留存 28% → 36%，年签单额 +35%
成本降本 X 万、单件成本 -X%结构优化使单台成本降低 18%，年度节税 80 万+
速度周期缩短 X 天、响应 < X ms接口 P99 从 800ms 降至 120ms
满意度 / 口碑评分 X、推荐率 X%、曝光 X 万患者满意度科室第一，单场活动曝光 3000 万+
实在没有精确数字：写区间或相对值也比空话强，例如「覆盖 5 个部门」「服务公司 70% 的订单」「行业内 TOP10」。诚实的估算 ≠ 造假，但绝不要编造具体金额或客户名。

四、强动作动词库：把「负责」换成有分量的词

动词开头 = 主动、有力。按岗位性质选词，同一个意思也别反复用同一个词。完整版（13 类、160+ 词，含例句）见 简历动作动词库。

领导 / 管理

主导牵头统筹搭建组建推动优化重构落地赋能

技术 / 研发

架构开发实现重构调优部署自动化接入迁移攻坚

销售 / 业绩

签下拓展维护攻下提升超越转化裂变回款谈判

运营 / 市场

策划操盘增长复盘起号拉新促活留存投放引爆

财务 / 风控

核算稽核筹划节税预警管控审计对账盘点合规

沟通 / 协作

协调对接推动汇报培训带教沉淀输出跨部门协作对外谈判
一个词用一次：如果一段经历里出现 3 次「负责」，HR 会自动判定你没做过核心事。把重复的动词换掉，句子立刻有层次。

五、各行业技能清单：技能区怎么写才专业

技能不是越多越好，而是「命中 JD + 有分级 + 看得出会到什么程度」。各行业的核心技能、加分技能、常用工具与分级写法，整理在 行业技能清单。

分级词含义（面试要能扛住）建议用法
了解知道概念，未独立做过少用，写了等于没写
熟悉能在指导下完成日常工作技能区主力，可大量使用
熟练能独立完成并解决常规问题与岗位核心技能绑定使用
精通能解决疑难、能带人、能定方案慎用，面试官一定会深挖
❌ 弱：精通 Office，熟练使用电脑，了解一些编程。
✅ 强：后端：Java / Spring Cloud（熟练）、MySQL 调优（熟悉）、Redis 高并发（熟悉）；工具：Docker、K8s、Git。

六、ATS 优化：8 条硬规则

大公司先用 ATS 机器筛简历，关键词不对直接被刷。八条务必照做：

  1. 不用图片排版：机器读不出图片里的字，纯文字 + 清晰标题最稳。
  2. 结构简单：避免嵌套表格、文本框、分栏，很多 ATS 解析会错位。
  3. 照抄 JD 关键词：岗位写「数据分析」，你就别写「数据处理」，机器按字面匹配。
  4. 用标准标题：工作经历、教育背景、专业技能、项目经历 —— 这些机器认得，别自创「我的旅程」。
  5. 技能关键词前置：把岗位核心技能自然写进「个人简介」和「技能」区，命中率最高。
  6. 用规范文件名：姓名-岗位-年限.pdf，别用「简历最终版2」。
  7. 导出 PDF 且字体可复制：扫描件、图片式 PDF 等于不可读。
  8. 按 JD 定制：同一岗位换 3 个关键词，通过率差异可能翻倍。

不确定能不能过？用 ATS 友好检测 自查一遍。

  • 全文没有一个「精通」却答不上来的技能

  • PDF 文字可复制、可搜索
  • 文件名规范：姓名-岗位-年限.pdf
  • 邮箱正式（姓名拼音），无尴尬昵称
  • 所有专有名词、公司名、数字核对无误
  • 没有与目标岗位完全无关的荣誉堆砌
  • 整页 HR 扫读 6 秒内能找到职位与核心成果
  • 按目标 JD 微调过关键词，而非通用版

九、不同人群的侧重点

应届生 / 校招

教育、实习、项目、竞赛往前放；没有工作经历就用课程项目、比赛、社团里能证明目标岗位能力的「可迁移成果」替代。详见 校招简历专项。

转行 / 跨岗

简介里第一句就讲清转行逻辑，把过往经历里与新岗位相通的能力拎出来（如做销售转运营：用户洞察、抗压、数据敏感）。用「相关项目 + 自学成果 + 证书」补足专业证据。

空窗期

不要留白，也用不着编造。一句话说明（系统学习 / 自由职业 / 家庭原因），紧接着写这段时间的产出或学习成果，把重心拉回「我现在能做什么」。

宝妈复出 / 重返职场

把育儿期管理家庭的能力转化为可迁移表达（时间管理、多任务统筹、预算规划）；复出前后可先做小项目、兼职或接单，把最近的一段经历填上，避免时间线长期空白。

资深 / 管理岗

突出「带多少人、管多大盘、定了什么策略、拿到什么业务结果」，执行细节一句带过。用团队规模、业务体量、组织效率这类「盘面数字」证明层级。

十、20 个高频错误，中一个就要改

  • 1. 通篇「负责」，看不到成果
  • 2. 一个数字都没有，全是形容词
  • 3. 用图片或复杂表格排版，ATS 读不出来
  • 4. 一份简历投所有岗位，不做定制
  • 5. 写年龄、婚育、身高体重、身份证号
  • 6. 放生活照（非硬性要求岗位）
  • 7. 技能写「精通 Office」这类无效信息
  • 8. 写了「精通」却答不上来，面试翻车
  • 9. 时间线有空档却完全不解释
  • 10. 错别字、公司名写错、数字前后不一致
  • 11. 篇幅失控：应届生写 3 页
  • 12. 花哨模板，可读性极差
  • 13. 邮箱 / 文件名不专业
  • 14. 项目只写团队成果，看不出你的贡献
  • 15. 教育背景里硬写低 GPA
  • 16. 堆砌与岗位无关的证书与荣誉
  • 17. 自我评价写「学习能力强、抗压能力强」等空话
  • 18. 造假经历或业绩，背景调查必翻车
  • 19. 正文小于 10pt，HR 看不清
  • 20. 完全没有针对 JD 的关键词

十一、常见问题 FAQ

简历写一页还是两页？

应届生与 5 年以内经验建议一页；资深或管理岗可两页。核心不是页数，而是每条信息是否与岗位相关——宁可两页写满干货，也不要一页塞满空话。

没有工作经历怎么写？

用实习、课程项目、竞赛、社团、自媒体、接单等「可迁移经历」替代：写清你负责什么、用了什么方法、拿到什么可量化的结果，再补技能与证书。专业匹配度往往比空泛的工作经历更高。

要不要放照片？

除模特、主播、部分服务业明确要求外，一般不建议。照片占空间、可能触发外貌偏见，部分 ATS 也解析不了图片。把空间留给经历与成果更划算。

什么是 ATS，会被机器刷掉吗？

ATS 是企业自动筛选简历的系统，按关键词、标题结构、文件格式打分。避免图片与复杂表格、按 JD 原词写关键词、使用标准标题与规范文件名，就能显著提高通过率。

量化数字写不出来怎么办？

用效率、规模、质量、增长、成本、速度、满意度七类口径去估算，写成区间或相对值也可以，如「覆盖 5 个部门」「服务公司 70% 的订单」。只要不是空话，相对数字同样有说服力。

空窗期 / 转行怎么处理？

诚实带过，重点放在「现在能做什么」。一句话说明原因，紧接着写这段时间获得的能力或成果，以及转行逻辑与已具备的通用能力。不要留白，也不要编造。

文件名和邮箱有讲究吗？

有。文件名用「姓名-岗位-年限.pdf」，别用「简历最终版2」；邮箱用姓名拼音或缩写，不要用非正式昵称；导出优先 PDF，避免不同设备下排版错乱。

一份简历能投所有岗位吗？

不建议。按目标 JD 微调技能关键词、调整经历顺序、替换更贴近的项目，命中率通常能提升数倍。改动 10 分钟，回报很高。
